# Retail Autopilot

Retail Autopilot помогает розничным сетям одежды распределять товар между магазинами. Если в одном магазине определённый размер остаётся на полке, а в другом его не хватает, сервис проверяет, успеет ли товар продаться до уценки и окупится ли перевозка. Для новой коллекции сервис рассчитывает, сколько единиц отправить в каждый магазин при первой поставке.

| Версия | Откуда берутся данные | Что получается |
| --- | --- | --- |
| [Версия 1](Версия%201/) | Остатки, спрос, цены и параметры доставки вводятся вручную | План перемещений с объяснением и выгрузкой для магазинов |
| [Версия 2](Версия%202/) | Сервис периодически получает снимки остатков, маршрутов, истории продаж и новых партий из CRM через API | Задания на перемещение и распределение первой поставки, статусы и журнал обмена |

## Версия 1. Ручной ввод

Скачайте репозиторий и откройте файл [index.html](Версия%201/index.html) в браузере. Перейдите в **Изменить данные и доставку**, замените срок до уценки с 14 на 2 дня и нажмите **Сохранить и показать новый план**. Сравните маршруты и количества до и после изменения. Можно изменить остатки, спрос и доставку, а затем скачать таблицу с планом.

## Версия 2. Автоматический обмен с CRM

Откройте терминал в папке **Версия 2** и запустите на Python 3.9 или новее. Дополнительные пакеты не нужны. Пример для macOS и Linux:

```sh
python3 app.py --snapshot crm-data/01-baseline.json
```

В Windows используйте `py -3 app.py --snapshot crm-data/01-baseline.json`. Панель — http://127.0.0.1:8765. Для переключения снимка остановите процесс через Ctrl+C и запустите его с другим файлом. Снимок загружается в учебную CRM, а приложение получает его через HTTP и записывает задания обратно. Каждый набор хранит своё состояние. Повторные проверки не дублируют уже принятые задания.

| Снимок CRM | Ожидаемый результат первого запуска |
| --- | --- |
| [01-baseline.json](Версия%202/crm-data/01-baseline.json) | Два перемещения и распределение новой партии из 60 единиц по истории продаж |
| [02-balanced.json](Версия%202/crm-data/02-balanced.json) | Дефицита нет, заданий нет |
| [03-expensive-routes.json](Версия%202/crm-data/03-expensive-routes.json) | Перевозки дороже ожидаемого выигрыша, заданий нет |
| [04-late-routes.json](Версия%202/crm-data/04-late-routes.json) | Товар не успеет продаваться по полной цене после доставки, заданий нет |
| [05-incoming-stock.json](Версия%202/crm-data/05-incoming-stock.json) | Входящая поставка закрывает дефицит джинсов на Тверской, остаётся одно перемещение рубашек |
| [06-new-size.json](Версия%202/crm-data/06-new-size.json) | 17 единиц нового размера распределяются почти поровну между тремя магазинами, поскольку истории по размеру пока нет |

Все шесть наборов содержат синтетические данные. Для подключения сети нужен адаптер CRM и системы учёта запасов. Контракт API, режим работы с адаптером и описание расчётов приведены в [документации второй версии](Версия%202/README.md).

## Экономический эффект

Основной эффект — **Less Money**. Более точная первая поставка сокращает расходы на перевозки между магазинами в течение сезона. Для пилота можно сравнить расходы на перемещения на единицу товара и долю продаж без скидки с текущим методом распределения. Прогноз спроса опирается на продажи за дни, когда нужная модель и размер были в наличии. Ожидаемый выигрыш от отдельных перемещений рассчитывается после вычета стоимости доставки.
